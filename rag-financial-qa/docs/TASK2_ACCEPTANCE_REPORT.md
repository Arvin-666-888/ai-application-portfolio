## 公平性缺陷与修复

第一次完整运行曾显示旧版 6.67%、新版 26.67%、提升 20 点。逐题审计发现该结果不公平：原 matcher 在做数值边界检查前删除所有空白，把旧版纯文本中相邻年份值：

```text
416,161 391,035 383,285
```

拼成：

```text
416161391035383285
```

导致正确的旧版 Top-1 被误判为数值子串。新版 Markdown 有 `|` 分隔符，未受同等影响，因此原 20 点结果系统性偏向新版，不能作为验收证据。

修复后：

- 期望值仍移除千位逗号和内部空白。
- 内容只压缩空白为单个分隔符，不再连接相邻表格数字。
- 保留 `100` 不命中 `1000`、`8.6` 不命中 `18.6` 的数值边界要求。
- 新增旧版表格文本 `416,161 391,035 383,285` 的回归测试。

历史本地 artifact `compare_result_en_10k.json` 保留第一次完整成功运行的真实 inventory、解析运行时、逐题 Top-5 和 `parse_failure_count=0`，并使用修复后的 `score_case` 对这些实际 Top-5 上下文重算命中。重算未重新解析 PDF、未重新调用 Embedding、未重新查询 Chroma；当时 artifact 中的 `metric_recalculation` 明确记录该边界。第二次完整重跑因耗时被停止，仅产生 `INVENTORY_OK` 和部分解析日志，未产生 `COMPLETED`，也因临时文件 + `os.replace` 机制而没有覆盖现有结果。该 JSON 未纳入本次正式提交白名单，本文保留历史指标与边界，但不把它作为公开仓库链接或关键流程依赖。
