# 项目答辩速览

## 一句话介绍

这是一个面向上市公司财报和公告的 RAG 智能问答后端原型。它支持文档上传、切分、向量化、检索、引用溯源、多轮问答、流式输出和资料外拒答，重点展示 AI 应用开发工程师需要的 RAG 落地能力。

## 面试官应该看到的能力

1. **AI 应用链路**：理解 RAG 的入库阶段和问答阶段，并能用代码实现。
2. **后端工程能力**：FastAPI 分层架构、JWT 鉴权、SQLite 元数据、ChromaDB 向量库。
3. **可信问答意识**：来源引用、资料外拒答、金融高风险问题护栏。
4. **效果评估意识**：JSONL 评测集、检索命中率、引用支撑率、拒答准确率。
5. **可交付意识**：`.env.example`、Dockerfile、docker compose、pytest、失败原因记录。

## 技术路线

```text
上传文件
  -> 解析 TXT/MD/PDF
  -> RecursiveTextSplitter 分块
  -> Embedding API / mock embedding
  -> ChromaDB collection
  -> 用户提问
  -> 向量候选召回
  -> 关键词重叠重排
  -> Prompt 注入上下文
  -> LLM 生成回答
  -> 返回 answer + sources
```

## 可以主动讲的设计取舍

- **为什么返回来源**：金融问答不能只给结论，必须能核验依据。
- **为什么有拒答**：RAG 不是让模型回答所有问题，而是让模型基于资料回答；资料没有覆盖时应拒答。
- **为什么加关键词重排**：纯向量检索在数字、年份、短问题上可能不稳定，轻量 lexical score 可以补足部分精确匹配能力。
- **为什么支持 mock mode**：方便没有 API Key 时演示接口链路，但真实效果必须用真实 embedding 和 chat 模型评估。
- **为什么不用生产级方案**：这是求职展示型原型，优先完整体现链路；生产环境需要队列、对象存储、权限模型、日志审计和更严格评测。

## 简历版项目描述

**上市公司财报与公告智能问答系统｜FastAPI / ChromaDB / RAG**

- 构建金融文档 RAG 问答后端，支持财报/公告上传、文本切分、Embedding 向量化、ChromaDB 检索、Prompt 生成和中文问答。
- 设计用户、知识库、文档、对话和消息模型，实现 JWT 鉴权、知识库管理、文档状态跟踪、失败原因记录、多轮对话和 SSE 流式响应。
- 在向量召回基础上加入关键词重叠重排、相关度过滤和来源引用，返回支撑答案的文档片段，提升答案可核验性。
- 设计资料外拒答和股价预测/买卖建议类金融护栏，减少幻觉和无依据投资建议输出。
- 编写 JSONL 评测集和评测脚本，统计检索命中率、引用支撑率、拒答准确率和答案关键词命中率，并补充 Docker 与 pytest 支持。

## 面试问答准备

**Q：RAG 流程怎么实现？**

文档入库阶段负责解析、切分、embedding 和写入 ChromaDB；问答阶段把问题 embedding 后检索 Top-K 候选，再结合关键词分数重排，最后把上下文放进 Prompt 让模型回答。

**Q：如何降低幻觉？**

第一，Prompt 要求只基于资料回答；第二，检索结果返回来源，便于核验；第三，资料外问题和股价预测类问题直接拒答；第四，用评测集检查拒答准确率。

**Q：这个项目的不足是什么？**

当前是求职展示型原型，不是生产投研平台。主要不足是复杂 PDF 表格处理、真实大规模评测、reranker、权限审计和部署架构还比较基础。
